# Security policy

## Supported versions

Security fixes go into the latest release only. There are no backports to earlier versions, so upgrade to the latest release before reporting a problem.

## Reporting a vulnerability

Please don't open a public issue, pull request or discussion about a vulnerability. Report it privately through [GitHub's private vulnerability reporting](https://github.com/breww-oss/django-deferred-migrations/security/advisories/new).

Include the version of django-deferred-migrations, your Django, Python and PostgreSQL versions, and the steps that reproduce the problem.

If you can't use GitHub's private reporting, open a normal issue that says only that you have a security report to make. Leave out every detail of the problem itself. We'll reply there and set up a private thread for the details.

## What happens next

- We acknowledge your report within three working days.
- Within ten working days we tell you whether we consider it a vulnerability, and why.
- If it is one, we agree a disclosure timeline with you before anything is made public.
- The published advisory credits you, unless you'd rather it didn't.
